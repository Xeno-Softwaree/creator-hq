# Phase 2.0 Package 1 — execution preparation

This is a local-only, disabled execution prototype. It does not deploy over the active Phase 1.3 build, launch Codex, change the database, or grant approval. The existing `ExecutionJob_disabled_check` constraint remains unchanged. Human owner profile `ceo` is never an executable agent.

## Contract and authority

Contract version 1 binds the exact task ID (or unsaved draft), title, description, agent ID, studio, role policy version, effective instructions, provided-text scope, fresh-job session policy, permission set and timeout. Canonical SHA-256 binds every contract field; JSON property ordering does not affect the digest. A trusted approval must identify the job, human owner, digest, decision and expiry. Agents cannot create approvals through model output. Changing any bound field invalidates the approval. Profile defaults supplement existing instructions without updating any stored profile.

`POST /execution/preview` reads the current profile and, when supplied, verifies the existing task fields. It rejects unknown/disabled profiles, the human owner, studio mismatch, unexpected properties and recognizable credential-bearing input. It returns `source=preview`, `enabled=false`, an invalid/unrequested approval, the contract and digest. `POST /execution/route` returns only an Atlas assignment proposal; `GET /execution/policies` describes the nine defaults. None saves a job or decision. There is no start or approval endpoint. Existing simulation and approval routes remain unchanged and cannot activate execution.

## Fake execution and events

`FakeCodexAdapter` only accepts fake processes constructed by this module (identity checked with a WeakSet); it contains no subprocess, shell, filesystem or network launcher. A module-wide slot limits all adapter instances to one fake execution. Attempted UUIDs cannot restart in the same process; the test ledger is bounded and fails closed at capacity. This is not a durable distributed queue and must not be used as a production lock.

JSONL is bounded, parsed across string chunks and restricted to a single thread, turn, structured text result and completion in that order. Tool events and unsupported shapes fail closed. Final results have a strict versioned schema. A needs-approval outcome stays awaiting approval rather than completing an operation. Child errors and partial output are discarded on failure. Timeout/cancel stops only the owned fake process; no retries or delayed writes exist. Supplied secret values, encoded values and credential patterns reject output before return. This is defense in depth, not proof that arbitrary unknown secrets can be recognized. Never supply secrets as task context.

Fake results are always `source=simulation`, `provider=fake_codex`, `enabled=false`. Preview is a distinct source. UI source labels distinguish simulation, preview, manual board updates, future `codex` reports and unknown provenance; no real report is generated by this package. Existing manual Done reports do not prove agent execution.

## Windows and authentication boundary

The non-executable CLI plan requests read-only, JSONL, ephemeral sessions and ignores user configuration. Its prompt is intended for stdin, not shell interpolation. Result JSON Schema is provided separately; a future launcher must install it in the isolated job directory and pass the reviewed schema path. No executable path or spawn function is connected. The fake environment allowlist contains only `NO_COLOR=1`; parent PATH, NODE_OPTIONS, CODEX_HOME, database/admin URLs, PostgreSQL variables and API keys are never copied.

Read-only sandbox does **not** prove that private files cannot be read. Ignoring user config does **not** by itself prove that all project instructions, MCP, hooks, plugins or credentials are isolated. Before any real launch, validate the installed Windows sandbox with inaccessible sentinel files, denied writes and denied network/tool access. Run outside application, vault and media directories, using job-only supplied text. Global configuration must remain unchanged. Sharing the owner's authentication must not make credential files readable to model tools. The real launcher needs a reviewed OS-level containment design before approval; no `danger-full-access`, approval bypass, automatic review or inherited shell configuration is allowed.

CLI 0.166.0 and ChatGPT login were inspected in the preceding read-only review. Saved authentication can be reused according to [official non-interactive documentation](https://learn.chatgpt.com/docs/non-interactive-mode); current command options are described in the [official reference](https://learn.chatgpt.com/docs/cli/reference). No model request or account quota check was made in Package 1. No paid API key or external service is required by this design.

## UI and validation

The Approvals page includes a TR/EN contract preview, studio-scoped agent selection, existing-task or unsaved-draft input, explicit disabled approval action and translated future status legend. Edits clear the prior preview; stale asynchronous responses cannot restore it. The state legend is not a list of actual running jobs. Nothing is persisted by the preview.

## Smallest next gate

Review the execution contract and Windows containment experiment first. Obtain separate operator approval for the isolated local real-CLI test (including its local session/output writes), never with application secrets. Keep production execution disabled during that test. Only after its evidence is accepted, propose the smallest application migration: durable unique launch key, approval-to-job digest binding and atomic worker ownership/lease, using existing job metadata where practical. Provide the exact constraint change and rollback plan for separate migration approval. Add authenticated human approval and a scoped broker before enabling a production launcher. Do not remove the disabled constraint or treat this prototype's in-memory lock as production safety.

No additional database service, video rendering, real media access or disaster-recovery automation belongs to this package.
